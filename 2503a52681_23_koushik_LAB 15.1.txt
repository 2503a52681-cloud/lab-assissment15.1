TASK-3
Task: Add a sample S3 read-only policy that allows listing and reading from one bucket.

PROMPT:
Write a valid AWS IAM JSON policy that allows s3:ListBucket on one S3 bucket and s3:GetObject on objects in that bucket. Do not allow upload or delete actions. Use YOUR-BUCKET-NAME as a placeholder.

CODE:
Replace YOUR-BUCKET-NAME with the bucket name from your earlier S3 lab.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME"
    },
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}

OUTPUT / EXPECTED PERMISSIONS:
s3:ListBucket  – Allowed
s3:GetObject   – Allowed
s3:PutObject   – Denied by this policy
s3:DeleteObject – Denied by this policy

Explanation:
The policy allows listing the bucket and reading its objects. It does not include upload or delete permissions. AWS denies a request by default unless an applicable policy allows it.

TASK-4
Task: Test the policy using the IAM Policy Simulator. Test ListBucket, GetObject, PutObject, and DeleteObject.

PROMPT:
Explain how to test four S3 actions in the AWS IAM Policy Simulator using the sample read-only policy. Give the expected Allowed or Denied result for each action.

CODE / PROCEDURE:
1. Keep the Policy Simulator open.
2. Choose Add actions.
3. Choose S3.
4. Select the action named in the test table.
5. Enter the matching resource ARN.
6. Choose Simulate.
7. Record whether the result is Allowed or Denied.
8. Repeat for the next action.

RESOURCES:
Bucket ARN:
arn:aws:s3:::YOUR-BUCKET-NAME

Object ARN:
arn:aws:s3:::YOUR-BUCKET-NAME/sample.txt

OUTPUT / EXPECTED RESULT:

GetObject       arn:aws:s3:::YOUR-BUCKET-NAME/sample.txt      Allowed
PutObject       arn:aws:s3:::YOUR-BUCKET-NAME/sample.txt      Denied
DeleteObject    arn:aws:s3:::YOUR-BUCKET-NAME/sample.txt      Denied

The expected results follow the sample policy. Replace the placeholder bucket name with your actual bucket name in the simulator.

TASK-5
Task: Connect IAM permissions to your team product.

PROMPT:
Write 3–4 simple sentences explaining which part of a team product needs AWS access, which AWS resource it needs, the minimum permission required, and one action it should not be allowed to perform. State that this is only a proposed permission design.

CODE / ANSWER:
“Our product’s backend needs to display files stored in our team’s S3 bucket. It needs permission to read those files using s3:GetObject. It may also need s3:ListBucket to list the files in the bucket. It does not need permission to delete files using s3:DeleteObject. We tested this permission idea in the Policy Simulator; we did not change AWS access.”

OUTPUT:
Product component: Backend application
AWS resource: Team S3 bucket
Minimum read permission: s3:GetObject
Listing permission, if required: s3:ListBucket
Action not allowed: s3:DeleteObject
Result: The proposed permissions follow the principle of least privilege.
